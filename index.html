splashes.json must always be placed directly inside the root directory of your Resource Pack (e.g. RP/splashes.json), right alongside your manifest.json and pack_icon.png. It should never be placed inside the texts/ directory.
loading_messages.json must also be placed directly in the root directory of your Resource Pack (e.g. RP/loading_messages.json). Placing it inside the texts/ folder will prevent Minecraft from recognizing your custom loading tips.
Starting in Minecraft Bedrock 1.21.40+, Mojang introduced the Bedrock Archive format (.brarchive). It bundles the dozens of loose JSON and metadata files within a directory (such as textures/ or sounds/) into a single uncompressed container placed under __brarchive/. This dramatically decreases filesystem read overhead and optimizes game loading times.
The __brarchive Maker allows you to drag and drop or manually stage files and compiles them into a valid binary .brarchive file matching Bedrock's 16-byte magic header specification. The __brarchive Reverter reads any .brarchive container, parses its table of entries, displays real-time previews of the embedded text/JSON assets, and lets you extract them back into original loose files.
The client_data module type is used primarily for client-side scripts, client-bound modules, or specialized UI scripts. While standard resource packs use resources for textures, models, and audio, client_data is specified when delivering client-bound script execution or custom client-side logic to the game engine.
No. Subpacks and Pack Settings are only supported by Resource Packs (resources) and select Behavior Packs (data). World templates (world_template) and skin packs (skin_pack) rely on strict, predefined structures (such as fixed world save files or skins.json) and do not support in-game manifest settings or subpack folders.
format_version 3 introduces support for newer and more advanced pack features like Pack Settings (toggles and dropdowns in the UI) and advanced Subpacks. Using version 3 typically requires a higher min_engine_version (usually 1.26.0 or newer) to function correctly in-game. Version 2 is the legacy format used for simpler packs.
The memory_performance_tier property is used within subpacks to define the hardware requirements for that specific subpack configuration. Higher tiers will automatically disable the subpack on lower-end devices (like older mobile phones) with limited RAM, which prevents the game from crashing due to high-resolution textures or heavy models. 0 is the default/lowest tier.
Capabilities (such as pbr, raytraced, or experimental_custom_ui) tell the Minecraft engine that your pack requires specific rendering engines or experimental toggles to function. For example, adding pbr enables Physically Based Rendering for Deferred Graphics.
A UUID (Universally Unique Identifier) is a random string of characters that Minecraft uses to identify your pack. Every pack and module must have a completely unique UUID. If two packs share the same UUID, Minecraft will think they are the same pack and will fail to load one of them. This generator automatically creates secure, randomized UUIDs for you!
Yes! Subpacks allow you to bundle multiple variations of your pack into one file. Players will see a gear icon next to your pack in-game, allowing them to choose between different resolutions, UI styles, or features by moving a slider.
Pack Settings allow you to create interactive UI elements like dropdown menus and toggles within your pack's configuration screen. When set up correctly in format_version 3, these settings can map to specific behavior pack variables, allowing players to customize exactly how your add-on behaves without needing separate subpacks.
min_engine_version sets the minimum Minecraft game version required to load your pack. If a player attempts to use your pack on an older version of Minecraft than what is specified here, the game will reject or flag the pack as incompatible.
The modules array tells Minecraft what functional components exist inside your pack. Common types include resources (textures, UI, audio), data (behaviors, entities, loot tables), skin_pack, world_template, and client_data.
Resource Packs (resources) manage client-side visual and audio assets such as block/item textures, 3D entity models, custom UI, and sounds. Behavior Packs (data) run server-side logic controlling entity AI, custom craft recipes, item mechanics, loot drops, and scripts.
Instead of hardcoding a raw title like "My Pack", you enter a translation key such as pack.name or pack.description in the manifest. Then inside your pack's texts/en_US.lang file, you add pack.name=My Pack Name. This allows your pack's name and description to automatically translate into different languages based on player game settings.
Minecraft Bedrock uses the section sign § followed by a color code to style text in names and subpack descriptions. For example, §aGreen Text, §cRed Text, §lBold Text, or §8Dark Gray Text.
The raytraced capability signals to the Bedrock engine that your resource pack contains DirectX Raytracing (RTX) PBR textures (normals, roughness, heightmaps, and metallic maps) allowing hardware-accelerated ray tracing to be toggled on Windows 10/11 RTX systems.
Dependencies link your pack to another required pack (such as linking a Behavior Pack to its corresponding Resource Pack by UUID) or to Minecraft Script API modules (such as @minecraft/server).

To release an update for your existing pack, keep the exact same Header and Module UUIDs, but increment the version number (e.g. from 1.0.0 to 1.0.1). Minecraft will detect the newer version number and seamlessly update the existing pack without corrupting worlds.
pack_optimization_version is an optional header property used in official Marketplace and modern Bedrock optimization pipelines to specify asset optimization schemas for low-memory platforms.
format_version: 1 is the legacy manifest format originally used in early versions of Minecraft Bedrock and standalone skin packs. Version 2 and 3 are standard for modern Add-On development.

About

mcpack generator

A rapid, web-based toolkit designed to create and manage essential Minecraft Bedrock Edition files, including manifest.json, splashes.json, loading_messages.json, and Bedrock Archive .brarchive bundles.

Supports modern pack types (Resource Packs, Behavior Packs, Skin Packs, World Templates, and Client Data), advanced Subpack & Setting configurations, and full packaging/decompilation of Mojang's modern __brarchive load optimization containers.
