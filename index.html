FAQ

splashes.json must always be placed directly in the root directory of your Resource Pack (e.g. RP/splashes.json), alongside manifest.json and pack_icon.png. It should never be placed inside the texts/ folder.
loading_messages.json must always be placed directly in the root directory of your Resource Pack (e.g. RP/loading_messages.json). Placing it inside the texts/ folder will cause Minecraft to ignore your custom loading screen tips.
Introduced in Minecraft Bedrock 1.21.40+, the Bedrock Archive format (.brarchive) bundles multiple loose files within a directory (such as textures, sounds, or UI JSONs) into a single contiguous binary container placed inside a __brarchive/ folder. This eliminates filesystem overhead and drastically improves pack load times.
The brarchive Maker compiles staged files into a valid binary .brarchive container matching Bedrock's 16-byte magic header specification (0x7D2725B1A0527026). The brarchive Converter decompiles any .brarchive container, previews the contents, and exports them as loose files or a bundled .zip.
manifest.json must always reside directly in the root directory of your pack (e.g. MyPack_RP/manifest.json or MyPack_BP/manifest.json). If it is placed inside any subfolder, Minecraft will fail to recognize the pack.
pack_icon.png must be a square PNG image placed in the root directory of your pack. Standard supported resolutions are 64x64, 128x128, 256x256, or 512x512 pixels. Non-square aspect ratios may appear distorted in the in-game settings menu.
sounds.json belongs in the root directory of your Resource Pack (RP/sounds.json) to define individual block/item sound event mappings. In contrast, sound_definitions.json belongs inside the sounds/ folder (RP/sounds/sound_definitions.json) to define sound categories, audio file paths, volume, and pitch.
All language translation files (such as en_US.lang, es_ES.lang, ja_JP.lang) and the supported languages manifest (languages.json) must be placed inside the texts/ folder of your pack (e.g. RP/texts/en_US.lang).
Version 1 is the legacy format originally used in early Bedrock editions and standalone skin packs.
Version 2 is the universal standard format for modern Resource and Behavior Packs.
Version 3 adds native support for in-game interactive Pack Settings (toggles and dropdowns) and advanced Subpacks, typically paired with min_engine_version 1.26.0 or newer.
A UUID (Universally Unique Identifier) is a 128-bit randomized string that Minecraft uses to uniquely identify packs and modules. The header UUID identifies the entire pack, while each entry in modules has its own unique UUID. Reusing a UUID across different packs causes "Duplicate Pack Detected" or silent pack loading collisions.
Keep the exact same Header and Module UUIDs, but increment the version array (e.g. from [1, 0, 0] to [1, 0, 1]). Minecraft will detect the newer version and update the installed pack without corrupting existing worlds.
min_engine_version sets the minimum Minecraft game client version required to load your pack. If a player attempts to load your pack on an older game version, Minecraft will mark the pack as incompatible and prevent it from activating.
Resource Packs (resources) manage client-side visuals and audio, including block/item textures, 3D entity models, UI JSON, animations, particles, and sounds.
Behavior Packs (data) run server-side logic controlling entity AI, custom components, loot tables, recipes, trading, and JavaScript/TypeScript Script API execution.
The client_data module type is used for client-bound scripts and custom UI bindings. While standard resource packs use resources for assets, client_data allows executing client-side scripts directly on the player client without running on the server.
Common capabilities include:
• pbr: Enables Physically Based Rendering (roughness, normal, height, metallic maps) for Deferred Technical Preview.
• raytraced: Enables hardware DirectX Raytracing (RTX) textures.
• experimental_custom_ui: Enables experimental custom UI scripting.
When subpacks are declared in manifest.json, create a subpacks/ directory in your pack root. Inside it, create subfolders matching each subpack's folder_name (e.g. subpacks/16x/, subpacks/32x/). Any assets inside the selected subpack folder will override the base pack assets when chosen by the player via the in-game settings slider.
memory_performance_tier specifies hardware RAM requirements for a subpack option. Higher tiers prevent heavy subpacks (such as 128x texture resolutions) from loading on low-memory mobile devices to prevent Out-Of-Memory (OOM) game crashes. 0 is the default/lowest tier.
Pack Settings allow creators to build custom interactive toggles and dropdown selectors directly inside the pack's settings menu. These variables can be queried in scripts or UI to toggle feature sets dynamically without creating dozens of separate packs.
Minecraft Bedrock uses the section sign § followed by a formatting character. Examples include §a (Green), §b (Aqua), §c (Red), §e (Yellow), §l (Bold), §o (Italic), and §r (Reset).
The dependencies array links your pack to another required pack (e.g. linking a Behavior Pack to its matching Resource Pack by UUID) or to official Minecraft Script API modules (such as @minecraft/server or @minecraft/server-ui).

2. Compress them into a standard .zip file.
3. Rename the file extension from .zip to .mcpack.
4. To package both a Resource and Behavior pack together, zip both .mcpack files into one archive and rename the extension to .mcaddon.
Common reasons include:
• Folder nesting: The zip contains a parent folder instead of placing manifest.json at the root.
• JSON syntax errors: Missing commas, unclosed brackets, or invalid quotes in manifest.json.
• Duplicate UUIDs: The header UUID matches a pack already installed on your device.
• Incompatible min_engine_version: The specified engine version is higher than your current Minecraft client.

About

mcpack generator

A rapid, web-based toolkit designed to create and manage essential Minecraft Bedrock Edition files, including manifest.json, splashes.json, loading_messages.json, and Bedrock Archive .brarchive bundles.

Supports modern pack types (Resource Packs, Behavior Packs, Skin Packs, World Templates, and Client Data), advanced Subpack & Setting configurations, and full packaging/decompilation of Mojang's modern brarchive load optimization containers.
